# 발표 페이지별 대본

## 1. 표지
안녕하세요. 저희 프로젝트는 강원도 맞춤형 응급 및 상시 병원 안내 시스템입니다.
사용자가 본인의 증상을 자연어로 입력하면, 시스템이 증상군과 의심 질환, 추천 진료과를 예측하고, 필요한 경우에만 추가 문진을 진행합니다.
그 결과를 바탕으로 응급도를 판단하고, 현재 위치에서 갈 수 있는 병원을 추천하는 것을 목표로 했습니다.

## 2. 문제 정의
이 프로젝트의 출발점은 사용자가 아플 때 자신의 증상을 말할 수는 있지만, 어느 진료과를 가야 하는지, 응급실을 가야 하는지, 어느 병원이 적절한지 판단하기 어렵다는 점이었습니다.
특히 강원도처럼 지역적으로 병원 접근성이 일정하지 않은 환경에서는 단순히 가까운 병원을 보여주는 것만으로는 부족합니다.
그래서 저희는 증상 입력과 병원 선택 사이에 있는 판단 과정을 데이터 기반 시스템으로 연결하고자 했습니다.

## 3. 프로젝트 목표
프로젝트 목표는 크게 네 가지입니다.
첫째, 자연어 증상을 기반으로 증상군, 진료과, 의심 질환을 예측하는 모델을 만드는 것입니다.
둘째, 모든 사용자에게 같은 질문을 하는 것이 아니라 예측된 질환에 맞춰 필요한 질문만 선택하는 것입니다.
셋째, 응급도는 질환 예측과 별도로 위험 신호와 문진 답변을 반영해 계산합니다.
마지막으로 병원 추천은 거리뿐 아니라 진료과, 병상, 이동 시간까지 함께 고려하도록 구성했습니다.

## 4. 전체 시스템 구조
전체 흐름은 사용자가 증상을 입력하는 것에서 시작합니다.
입력 문장은 symptom_classifier 모델로 들어가고, 모델은 증상군과 진료과, 의심 질환 후보를 예측합니다.
이후 disease_question_map에서 해당 질환에 맞는 질문을 골라 추가 문진을 진행하고, 문진 답변까지 합쳐 최종 응급도를 계산합니다.
마지막으로 진료과와 병상 정보, 거리와 ETA를 반영해 병원을 추천합니다.

## 5. 데이터 파이프라인
데이터 파이프라인은 문제 정의, 데이터 수집, 데이터 정제, 데이터 탐색, 분석 결과 활용 순서로 구성했습니다.
네이버 지식인 크롤링 데이터는 실제 사람들이 쓰는 자연어 증상 표현을 확보하기 위해 사용했습니다.
이후 비의료 사례나 동물, 꿈, 법률 상담처럼 목적과 맞지 않는 데이터를 필터링하고, 질환명과 진료과를 통합했습니다.
정리된 데이터는 모델 학습, 문진 질문 선택, 응급도 계산, 병원 추천에 각각 분리해서 활용했습니다.

## 6. 사용 데이터 한눈에 보기
저희 시스템은 네이버 지식인 데이터만 사용한 시스템은 아닙니다.
네이버 지식인은 자연어 증상 표현과 모델 학습의 중심 데이터로 사용했습니다.
질환 마스터는 같은 질환이 여러 이름으로 표현되는 문제를 줄이기 위해 disease_id 기준으로 통합하는 역할을 합니다.
응급 문진 룰과 병상 CSV는 질환 판단용이 아니라 위험도 계산과 병원 추천 보조 데이터로 사용했고, 병원 기본정보는 상시 병원과 응급 병원 추천에 활용했습니다.
또한 서울아산병원 질환백과와 같은 의료 지식은 질환명, 증상, 진료과 체계를 보강하는 기준으로 참고했습니다.

## 7. 데이터 이해도
현재 시스템은 3,499건의 증상 사례, 149개의 질환 마스터, 118개의 학습 disease_id, 532개의 문진 질문을 기반으로 구성되어 있습니다.
중요한 점은 단순히 데이터를 많이 모은 것이 아니라, 서로 다른 데이터가 같은 질환 기준으로 연결되도록 만든 것입니다.
그래서 모델, 문진 질문, 응급 룰, 병원 추천 데이터가 모두 disease_id를 통해 같은 질환을 바라보도록 통합했습니다.
이 과정에서 매핑되지 않는 row가 남지 않도록 점검했습니다.

## 8. 라벨 통합: disease_master
의료 데이터에서 가장 어려웠던 부분 중 하나는 같은 질환이 서로 다른 이름으로 표현된다는 점이었습니다.
예를 들어 심근경색, 급성 심근경색, AMI는 표현은 다르지만 시스템에서는 같은 질환으로 다뤄야 합니다.
그래서 disease_master를 기준으로 질환명을 disease_id로 통합했습니다.
이렇게 해야 모델 결과, 문진 질문, 응급도 룰, 병원 추천이 서로 엇갈리지 않고 하나의 흐름으로 연결됩니다.

## 9. 서울아산병원 질환백과 활용
서울아산병원 질환백과는 학습 원문으로 그대로 넣기보다는, 의료 지식을 보강하는 기준으로 활용했습니다.
질환명, 대표 증상, 관련 진료과 같은 구조화된 정보를 참고해서 disease_master의 별칭, 증상 키워드, 진료과 매핑을 보완했습니다.
이 방식은 모델이 실제 사용자 표현은 네이버 지식인 데이터로 학습하되, 질환 체계는 의료 지식에 맞게 정리되도록 하기 위한 선택입니다.
즉, 질환백과는 모델을 대신 판단하는 데이터가 아니라 라벨과 진료과 체계를 안정화하는 보조 기준입니다.

## 10. 모델 설계
모델은 사용자의 자연어 증상 문장을 입력으로 받아 증상군, 추천 진료과, 의심 질환 TOP3를 출력합니다.
한국어 증상 문장은 띄어쓰기나 표현 차이가 크기 때문에 char TF-IDF 기반 표현을 사용했고, 여러 baseline과 비교하면서 최종 모델을 선택했습니다.
이 모델이 시스템의 핵심이며, 응급도 데이터는 질환을 판단하는 데 직접 사용하지 않고 이후 위험도 계산에만 사용했습니다.
이를 통해 질환 예측과 응급도 판단의 역할을 분리했습니다.

## 11. 추가 문진
추가 문진은 고정된 질문 네 개를 던지는 방식이 아닙니다.
모델이 예측한 질환과 증상군을 기준으로 disease_question_map에 있는 질문 후보를 랭킹합니다.
점수에는 질환 일치, 증상군 일치, risk_score, importance, 그리고 사용자가 이미 말한 정보에 대한 중복 패널티가 반영됩니다.
질문은 새로 생성하지 않고 미리 검토된 후보 중에서 고르기 때문에, 문진 흐름이 더 안정적으로 유지됩니다.

## 12. 응급도와 병원 추천
응급도는 질환 예측 결과만으로 결정하지 않고, red flag와 문진 답변의 risk_score를 함께 사용합니다.
예를 들어 호흡곤란, 의식저하, 편마비, 흉통 같은 위험 신호가 있으면 응급도가 높아집니다.
병원 추천에서는 진료과 매칭, 거리, ETA, 병상 정보를 함께 반영합니다.
특히 가용 병상이 0개인 병원은 단순히 가까워도 우선순위가 내려가도록 설계했습니다.

## 13. 사용한 API
외부 API는 모델 판단을 대신하는 용도가 아니라, 위치와 실시간성을 보완하는 용도로 사용했습니다.
Kakao Local API는 주소나 장소 검색을 통해 사용자의 위치 좌표를 설정하는 데 사용했습니다.
Kakao Mobility API는 병원까지의 자동차 이동 시간과 거리를 더 현실적으로 계산하는 데 사용했습니다.
공공데이터 EGEN API는 응급실 가용 병상 정보를 실시간으로 조회하는 데 사용했습니다.
그리고 백엔드는 FastAPI로 구성해 문진, 분석, 병원 추천 API를 제공합니다.
API가 실패하는 경우에는 정적 CSV 데이터나 ETA 모델로 fallback되도록 했습니다.

## 14. 실제 서비스 화면
실제 화면에서는 사용자가 증상을 입력하고 위치를 설정한 뒤 문진을 시작할 수 있습니다.
분석 결과 화면에서는 최종 응급도, 의심 질환, 추천 진료과, 증상군, 판단 요약, 추천 병원이 한 번에 표시됩니다.
사용자 입장에서는 복잡한 모델이나 데이터 구조를 몰라도, 지금 응급실을 가야 하는지, 어떤 진료과를 가야 하는지, 어느 병원이 적절한지 확인할 수 있습니다.
UI는 추천 점수 같은 내부 계산값은 숨기고, 사용자가 바로 이해해야 할 정보 중심으로 구성했습니다.

## 15. 실행 검증
최종 단계에서는 단순히 코드를 작성하는 데서 끝내지 않고 실제 실행 검증을 진행했습니다.
모델 로드, disease_master 로딩, mapped CSV 로딩, 백엔드 실행, smoke test, 주요 API 응답을 확인했습니다.
또한 질환 매핑 실패, 컬럼 불일치, confidence 계산 오류, 추천 로직 오류 같은 항목도 점검했습니다.
이를 통해 데이터 입력, 분석 실행, 결과 출력이 하나의 시스템으로 연결되는지 확인했습니다.

## 16. 마무리
정리하면 이 프로젝트는 진단을 대신하는 시스템이 아니라, 증상 입력 후 응급도와 병원 선택을 돕는 데이터 기반 안내 시스템입니다.
핵심 기여는 자연어 증상 데이터로 질환 후보를 예측하고, 질환별 문진을 통해 위험도를 보정하며, 위치와 병상 정보를 반영해 병원 추천까지 연결했다는 점입니다.
향후에는 더 많은 실제 의료 상담 데이터와 병상 API 안정성을 확보하면, 더 신뢰도 높은 지역 응급 안내 시스템으로 발전시킬 수 있습니다.
이상으로 발표를 마치겠습니다.
