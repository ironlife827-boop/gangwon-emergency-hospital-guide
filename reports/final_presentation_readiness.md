## 현재 강점

- 질환 판단의 중심을 `symptom_classifier.pkl`과 `disease_id` 기반 구조로 정리했다.
- 응급 룰은 질환 분류가 아니라 위험도 계산 보조로 사용한다.
- `disease_master.csv`와 mapped CSV 덕분에 라벨명이 조금 달라도 같은 질환으로 묶을 수 있다.
- 질문은 새로 생성하지 않고 `disease_question_map_mapped.csv` 후보 중에서 선택한다.
- 비응급 증상은 상시 병원 추천으로 이어질 수 있고, 응급 증상은 응급의료기관 추천으로 흐름이 나뉜다.
- 최종 검증에서 모델 로드, mapped CSV, backend 실행, 주요 API, smoke test가 통과했다.

## 현재 약점

- 모델 confidence가 낮은 케이스가 있어 “확정 진단”처럼 설명하면 안 된다.
- 일부 source/comment/문서에 한글 mojibake 흔적이 있다.
- 실시간 병상 데이터는 외부 API 키와 데이터 갱신 주기에 의존한다.
- 네이버 지식인 데이터는 실제 의료 정답셋이 아니라 사용자 표현 데이터이므로 평가 해석에 주의해야 한다.
- 희귀 증상이나 매우 짧은 입력은 fallback rule 의존도가 높다.

## 발표 시 강조해야 할 요소

- “진단 시스템”이 아니라 “응급도 판단 및 병원 안내 보조 시스템”이다.
- 모델은 단일 정답을 강요하지 않고 TOP3 의심 질환 후보를 제공한다.
- red flag는 모델 confidence와 무관하게 우선 적용된다.
- 일반 감기/알레르기 비염 같은 비응급도 상시 병원 추천으로 자연스럽게 처리한다.
- 질환 판단용 데이터와 응급도 계산용 데이터를 분리했다.
- `disease_id` 기반 통합으로 라벨명 불일치 문제를 줄였다.

## 교수 질문 예상 TOP20 및 권장 답변

1. Q: 이 시스템은 질병을 진단하나요?  
   A: 아닙니다. 진단이 아니라 응급도 판단과 병원 안내를 위한 보조 시스템입니다.

2. Q: 왜 네이버 지식인 데이터를 사용했나요?  
   A: 사용자가 실제로 입력하는 자연어 증상 표현을 확보하기 위해 사용했습니다.

3. Q: 라벨 정답셋은 어떻게 만들었나요?  
   A: 증상 사례에 symptom_group, department, suspected_disease, severity_level을 붙이고 disease_master로 정규화했습니다.

4. Q: 응급도 데이터로 질환을 맞히나요?  
   A: 아닙니다. 질환 후보는 symptom classifier가 예측하고, 응급도 데이터는 risk_score 보조 계산에 사용합니다.

5. Q: disease_master를 만든 이유는 무엇인가요?  
   A: 같은 질환이 다른 이름으로 저장되는 문제를 줄이고, disease_id로 데이터셋을 통합하기 위해서입니다.

6. Q: 모델은 어떤 입력을 받나요?  
   A: 사용자가 입력한 자연어 증상 문장입니다.

7. Q: 모델 출력은 무엇인가요?  
   A: symptom_group, department, suspected_disease, disease_id 기반 TOP3 후보입니다.

8. Q: 문진 질문은 어떻게 선택하나요?  
   A: disease_id 일치, symptom_group 일치, risk_score, importance, 이미 입력된 키워드 중복 여부로 랭킹합니다.

9. Q: 질문을 LLM으로 생성하나요?  
   A: 아닙니다. 저장된 `disease_question_map` 후보 중에서 선택합니다.

10. Q: 왜 TOP1만 보여주지 않나요?  
    A: 의료 증상은 모호성이 크기 때문에 후보군 형태가 더 안전하고 설명 가능합니다.

11. Q: red flag는 무엇인가요?  
    A: 호흡곤란, 의식저하, 편마비, 흉통 같은 즉시 응급 판단이 필요한 위험 신호입니다.

12. Q: red flag와 모델 예측이 충돌하면 어떻게 하나요?  
    A: 안전을 위해 red flag를 우선합니다.

13. Q: 비응급 증상도 처리하나요?  
    A: 네. 감기, 알레르기 비염, 위염 등은 낮은 응급도로 분류하고 상시 병원을 추천합니다.

14. Q: 병원 추천 기준은 무엇인가요?  
    A: 응급 여부, 진료과 매칭, 가용 병상, 거리/ETA, 야간 진료 여부 등을 종합합니다.

15. Q: 병상이 0개면 어떻게 되나요?  
    A: 응급 후보에서는 병상 점수에 큰 패널티를 주어 가용 병상이 있는 병원이 우선됩니다.

16. Q: 실시간 데이터는 어디까지 사용하나요?  
    A: Kakao 경로 ETA와 공공 응급의료기관 병상 조회 구조를 사용하며, 실패 시 정적 CSV/ETA 모델 fallback을 둡니다.

17. Q: 모델 성능 평가는 어떻게 했나요?  
    A: classification report, smoke test, 실제 API 검증, 발표 시나리오 테스트를 수행했습니다.

18. Q: 가장 큰 한계는 무엇인가요?  
    A: 사용자 표현 데이터 기반이라 의료진 확정 진단 수준의 정답성을 보장할 수 없다는 점입니다.

19. Q: 개인정보 문제는 없나요?  
    A: 현재 시스템은 사용자가 입력한 증상과 위치 좌표를 처리하며, 별도 개인 식별정보 저장 기능은 두지 않았습니다.

20. Q: 향후 개선한다면 무엇을 하겠나요?  
    A: 의료기관 검증 라벨셋 확보, 더 큰 일반 증상 데이터 보강, API 장애 모니터링, 모델 confidence calibration을 개선하겠습니다.
